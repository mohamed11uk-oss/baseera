# Known limitations (honest list)

1. **Evaluation data is synthetic.** Fraudulent URLs in `data/testset/labeled.csv` were invented by the team; precision/recall in docs/eval.md show the engine works as designed, not real-world accuracy. Next: import real PhishTank/OpenPhish rows filtered to UAE brands.
2. **Search/Maps data is synthetic.** `data/fixtures/serp/*.json` are written examples, labelled in UI and API. `scripts/record_demo_fixtures.py` can record real results (labelled `recorded <date>`), but nothing has been recorded yet. A SerpAPI key is now configured (`SERPAPI_KEY` or `SERPAPI_API_KEY`, loaded from the git-ignored `.env`), but the build box's network blocks outbound lookups, so the live path is verified only with mocked HTTP (tests/test_config_env.py), not against serpapi.com.
3. **Registry coverage.** 19 entities; only 9 have phones verified on official sites (2026-11-19). 10 are domain-only (some sites blocked automated fetches: ADCB, Emirates Post, Salik returned HTTP 403; du returned an error). A human must confirm those.
4. **Deep scan is new and lightly tested live; no LLM yet.** The headless-Chrome sandbox (opt-in, `deep: true`) was verified live only on example.com; all other tests use local synthetic HTML. Known gaps:
   - Clustering matches screenshot hashes **exactly** (strong key); near-duplicates (small Hamming distance) are not yet grouped. `sandbox.hamming()` exists for that.
   - DNS rebinding: **closed for suspect-site fetches** (Prompt 4.6). `safe_fetch` and `follow_redirects` resolve each hop once, validate every IP with `ssrf_check`, and connect only to that checked IP through a pinned httpcore network backend (`normalize.pinned_client`). The Host header, TLS SNI and certificate verification still use the hostname, and env proxies are ignored. A host that was never checked is refused. The TLS-certificate lookup (`domain_intel.tls_lookup`) also connects to the checked IP. The deep-scan sandbox is covered because Chrome never opens a socket itself: every request goes through `page.route` → `safe_fetch`. Still open: (a) the pin uses private httpx 0.28 internals (`transport._pool._network_backend`). An httpx upgrade that changes them makes fetches fail closed with an error, not unpinned (pinned in requirements.lock). (b) The fixed-host source clients (RDAP in `sources/domain_age.py`, feed downloads in `sources/feeds.py`) still check each hop in a request hook and then let httpx resolve again. Those hosts are rdap.org, registry RDAP servers and feed CDNs, not URLs the attacker chooses, so the risk is low. (c) Sandbox safety depends on Playwright routing catching every request. WebSockets are closed and DNS prefetch and non-proxied WebRTC UDP are disabled, but a Chrome bug that bypassed routing would also bypass the pin. (d) Verified offline (tests/test_dns_pinning.py, mocked socket layer) plus one live HTTPS GET to example.com. Rejection of a wrong certificate through the pinned path was not confirmed live: this box's egress proxy cut the TLS handshake first.
   - Field/brand detection reads the DOM through `page.evaluate`, so a hostile page could tamper with DOM APIs to hide fields (it cannot raise risk wrongly that way, only hide). Closed shadow DOM and canvas-drawn forms are not seen.
   - Chrome runs with `--no-sandbox` when the process is root (Chrome refuses otherwise). Run the server as a non-root user (or in a container) in production.
   - Screenshots under `data/runtime/screenshots/` are never deleted (no retention policy yet) and may contain personal data shown by the page.
   - One Chrome launch per deep scan (~1–3 s). No queue/concurrency limit: do not expose `deep: true` publicly.
   - No LLM vision step (Prompts 4.2/4.3): no ANTHROPIC_API_KEY available.
5. **Threat-intel feeds partly verified.** OpenPhish import verified live (2026-11-19). PhishTank import is implemented but the keyless download returned HTTP 404, so it needs an app key (unverified). Google Safe Browsing is implemented but untested live (no key). URLhaus, urlscan.io (read-only) and VirusTotal (manual deep check) are implemented but off by default and untested live (no keys). Feeds only refresh when someone runs `python -m baseera feeds refresh` (no scheduler).
6. **.ae domain age.** RDAP has no .ae data; the .ae WHOIS client exists but port 43 timed out from the build box and its output format is unverified. The fallback is the crt.sh first-certificate date, which is only a proxy (the domain may be older). crt.sh adds up to ~6s × 3 attempts of latency to a live analysis when RDAP has no date (cached afterwards).
7. **Generic lures without a brand** (e.g. parcel-redelivery-fee.top) and **raw-IP URLs** often score below medium — see FNs in docs/eval.md.
8. **Brand-keyword false positives** for legitimate businesses whose name contains a brand (e.g. an invented "salikcarrental.ae" scores medium). Mitigation: allow-list + LLM/page check.
9. **Security:** analyst endpoints are open unless `ANALYST_TOKEN` is set; `/api/analyze` and deep scan have no rate limit. CORS is closed except chrome-extension origins. Run on localhost for the demo; set the token and a reverse proxy before any public exposure.
10. **Clustering** uses infra fields that only exist in live mode (RDAP/TLS) or in the synthetic demo cases; offline-only cases cluster only on phone/path/target.
11. Pre-hackathon code: the team chose to build before 24 Nov accepting the risk; organisers' rules on pre-built code were not published at build time.
12. **Live-mode latency.** A brand scan in live mode can take ~10–25 s on first run (RDAP + crt.sh + TLS + redirects per listing, now in parallel; cached afterwards). Use offline mode or pre-warm caches before the demo.
13. **Claude Code stage 6 was interrupted** by the Claude Pro 5-hour usage limit (resets 13:50 Asia/Muscat, 19 Nov). Its work passed all tests and was committed; the docs part was finished directly.
14. **Pitch deck** (`docs/Baseera.pptx`, generated by `scripts/make_pptx.py`) contains only verified facts (Aman 8002626 / SMS 2828); no police fraud statistics are quoted because their source was not re-checked.
15. **Demo video** (`docs/baseera_demo.mp4`) was recorded in offline mode (the build box blocks outbound lookups); Search/Maps results shown in it are synthetic and labelled.
