Problem

Scammers impersonate UAE government entities, police, banks and telcos with look-alike domains, SMS / WhatsApp links and fake “customer service” numbers that appear in sponsored Search results and on Maps pins. One tap on a fake “fine” or “account blocked” link can hand over card details and the OTP. Residents need a fast, trustworthy answer; analysts need to see that many sites are one campaign and act with evidence.

Report fraud — Aman: call 8002626 · SMS 2828 (adpolice.gov.ae, checked 19 Nov 2026)

Solution & features

1. Link / SMS check. Paste a URL or message → risk 0–100 and the top-3 reasons in Arabic (English below), each tied to a named signal and its evidence.
2. Search & Maps check. Compares listing name, phone and website with an Official Entity Registry: sponsored look-alikes, fake support numbers, hijacked Maps pins. Unknown numbers are “unverified”, never “fake”.
3. Analyst dashboard. Risky verdicts become cases; cases cluster into campaigns by shared phone, IP, name servers, screenshot hash, registrar, path pattern and target. Node graph + timeline.
4. Evidence export. JSON / HTML / PDF / ZIP packs with SHA-256 hashes, UTC timestamps, redirect chain, signal sources and a draft report (never sent automatically).
5. Bilingual UI + browser extension. Arabic RTL interface with one-click English; Chrome (MV3) extension checks the current tab against the same API.
6. Offline mode. BASEERA_MODE=offline: no network at all, deterministic demo. Every live source is optional, with 4 s timeouts and caching.

How to run

./run.sh                          # creates .venv, installs deps, serves http://127.0.0.1:8000
BASEERA_MODE=offline ./run.sh     # no network at all (safest for a live demo)
make check                        # ruff + full offline test suite

Optional keys go in a git-ignored .env (template: .env.example), loaded automatically; e.g. SERPAPI_KEY (or SERPAPI_API_KEY) enables live Search/Maps results. Without keys Baseera still works. Browser extension: chrome://extensions → Developer mode → Load unpacked → extension/. Demo video: docs/baseera_demo.mp4.

Measured results (docs/eval.md)

105 URLs (43 fraudulent, 62 benign), threshold “medium” (risk ≥ 30): precision 0.98, recall 0.95, F1 0.96, false-positive rate 0.02, median 0.95 ms per URL offline. The fraudulent examples are synthetic look-alikes written by the team: this shows the engine behaves as designed, not real-world accuracy. No official registry domain is flagged (false-positive guard test).

Honest limits

  • Synthetic data: evaluation frauds, demo Search/Maps listings and demo campaigns are synthetic and labelled as such in UI, API and evidence.
  • Registry: 19 entities; only 9 have phones verified on official sites. Unlisted numbers are “unverified”.
  • Live SerpAPI is wired (key in .env) but verified only with mocked HTTP; the build machine blocks outbound lookups.
  • No LLM step yet (rules + registry). Brand-less lures and raw-IP links can score below medium.
  • Analyst endpoints are open unless ANALYST_TOKEN is set; no rate limiting. Run on localhost for the demo.
  • Full list: docs/LIMITATIONS.md.
